## Root causes and code

- Candidate011's scene cursor forced every 256-work poll through a Windows timer. Its native sidecar has 43,870 slices, 678,456.041 ms total Fiber work and 1,291,060.406 ms wall time: 612,604.365 ms outside Fiber execution. Scene resolver wall time includes that scheduling cost. Cursor unit polls now retain cancellation/progress but let the existing adaptive controller decide whether to yield; elapsed 6 ms and explicit boundary flushes still force. Auto 12 ms, UI coalescing and acceptance budgets are unchanged. Builder forwards the cursor's actual force bit.
- PNG repack consumed 230,522 ms of native optimizer time. Its per-byte five-filter search now uses equivalent scalar scores/Paeth distances and a bounded, invocation-local exact row-pair cache (32 entries / 2 MiB accounted payload). Tie order, samples, candidate choice and DEFLATE settings remain unchanged. Polls occur within wide rows, every row, and each 32 KiB DEFLATE input chunk. Reference RGBA hashing now receives the texture checkpoint.
- The real decode/fidelity call chain previously received no controller callback. Optional callbacks now flow through export job → extension → decoder/container/validator. Optional-three-argument validators are dispatched using their parameter list; genuine validation exceptions are never retried as arity errors. Full comparison still runs. Exact/Research avoid a face classification table whose result those profiles never consume.
- Container compression also polls within sections with `NO_FLUSH`, preserving the original byte stream. Decoder/fidelity loops expose cooperative work without adding state to the decoded document or changing tolerances.
